# Survey Bot — движок опросов для Discord (MVP)

Бот-конструктор опросов: создаёшь опрос через JSON-файл, публикуешь кнопку
"Пройти опрос" в любом канале, участник проходит опрос в приватном канале,
ответы экспортируются в CSV. Плюс вторая функция — **события с
ограниченным набором участников** и листом ожидания (см. раздел ниже).

## Возможности

- `/survey create` — загрузить JSON-файл с опросом (доступно только роли/админам)
- `/survey publish` — опубликовать кнопку "Пройти опрос" в текущем канале
- `/survey list` — список всех опросов
- `/survey results` — экспорт всех ответов в CSV (открывается в Excel/Google Sheets)
- `/survey delete` — удалить опрос и его ответы
- При прохождении опроса боту создаёт **приватный канал**, видимый только
  участнику и роли администраторов (в отдельной категории `📋 Опросы`).
  После завершения канал автоматически удаляется через 20 секунд.
- Поддержка типов вопросов: шкала (1–5), один вариант, несколько вариантов
  (с опцией "Другое"), да/нет с уточнением, свободный текст.
- Анонимность: если `"anonymous": true` в JSON, в CSV вместо ника будет
  "Аноним #1", "Аноним #2" и т.д.
- Защита от повторного прохождения (можно отключить через `"allow_multiple": true`).

## События с ограниченным набором участников (новое)

Вторая функция бота — события с лимитом мест, отдельная от опросов, но
живёт в том же боте/панели/базе.

- `/event create title:... description:... capacity:N date:ДД.ММ.ГГГГ time:ЧЧ:ММ role:@роль`
  — то же самое можно сделать командой в Discord, если удобнее.
- **Веб-панель → «🎫 События» → «+ Новое событие»** — создание полностью с сайта:
  название, описание, число мест, дата/время, а также **выпадающие списки** сервера,
  канала публикации и роли (подтягиваются напрямую из Discord через бота). После
  отправки формы бот сам публикует карточку и создаёт приватный канал — заходить в
  Discord для создания не нужно.
- На карточке две кнопки: **✅ Join** и **🚪 Leave**, подписи всегда на
  английском (Discord не может показывать разный текст разным людям на
  одном сообщении).
  - **🟢 Обычный режим** (по умолчанию) — пока есть места, «Join» даёт
    мгновенный доступ: роль + приватный канал. Когда лимит заполнен —
    новые нажатия сами уходят в **лист ожидания**.
  - **🔒 Ручной режим** — все нажатия «Join» идут в лист ожидания, даже
    если по факту есть свободные места (например, ты только что поднял
    лимит, но хочешь зачислять по одному сам). Включается/выключается на
    странице события в веб-панели, кнопкой «Переключить режим» — это
    отдельный переключатель, увеличение лимита само по себе режим не
    меняет.
- `/event list`, `/event close`, `/event delete` — вспомогательные команды
  в Discord (те же права, что и у управления опросами — админ-роль или
  права администратора). `/event close` включает ручной режим.
- **Веб-панель → «🎫 События»**: список событий, страница события с:
  - редактированием названия/описания/даты-времени;
  - **донабором** — увеличением лимита участников прямо в форме (никогда
    не переключает режим сама — обычный/ручной режим меняется отдельно);
  - переключателем режима приёма заявок (обычный / ручной);
  - листом ожидания, отсортированным по времени подачи заявки, с кнопками
    **Одобрить** / **Отклонить** — одобрение работает, только если в
    событии есть свободное место;
  - списком уже записанных (с датой записи) и возможностью убрать
    конкретного участника (роль и доступ к каналу снимаются автоматически);
  - экспортом списка участников в CSV;
  - удалением события (удаляет и приватный канал, и снимает роль со всех
    участников).
- Роль и канал, привязанные к событию, задаются один раз при создании —
  дальше через веб-панель их сменить нельзя (только текст, даты и лимит).
  Если понадобится сменить роль/канал — проще удалить и создать заново.
- Для работы выбора роли/канала и автовыдачи роли боту нужны права
  **«Управление каналами»** и **«Управление ролями»**, а роль бота в
  настройках сервера должна стоять **выше** той роли, которую он выдаёт
  участникам (иначе Discord запретит её выдавать).

## Выбор языка (EN / RU)

Третья функция — канал с двумя кнопками, где человек один раз выбирает язык,
на котором ему лично отвечает бот.

- `/language setup [channel]` — если канал не указан, бот создаёт свой
  (`🌐│choose-language`) с правами: все видят и могут жать кнопки, но писать
  текстом нельзя. Если канал указан — бот просто выставит эти права на нём
  и опубликует туда карточку.
- Две кнопки: 🇬🇧 **English** / 🇷🇺 **Русский**. Нажатие сохраняет выбор в
  базе на этого конкретного пользователя, по умолчанию (пока не нажал) —
  английский.
- **Важно, как это работает на практике**: сама карточка события (embed,
  подписи кнопок «Join»/«Leave») видна всем одинаково и всегда на английском
  — Discord физически не может показывать разный текст на одном сообщении
  разным людям. А вот **личные (эфемерные) ответы бота** — подтверждение
  записи, ошибки, сообщение «мест нет» и т.п., а также приветствие в
  приватном канале при входе конкретного участника — показываются на языке,
  который человек выбрал.
- `/language stats` — сколько людей выбрали EN, сколько RU.

## 1. Создание бота в Discord

1. Зайди на https://discord.com/developers/applications → **New Application**
2. Вкладка **Bot** → **Reset Token** → скопируй токен (это `DISCORD_TOKEN`)
3. Включи **Privileged Gateway Intents** — для этого бота не требуются
   специальные интенты (message content не нужен), можно ничего не включать
4. Вкладка **OAuth2 → URL Generator**:
   - Scopes: `bot`, `applications.commands`
   - Bot permissions: `Manage Channels`, `Send Messages`, `Embed Links`,
     `Read Message History`, `View Channels`, `Use Slash Commands`,
     `Attach Files`
   - Скопируй сгенерированную ссылку и пригласи бота на сервер

## 2. Узнай ID роли администраторов (кто может создавать/публиковать опросы)

В Discord: Настройки сервера → Роли → правый клик на роль → **Copy Role ID**
(нужен включённый режим разработчика: Настройки пользователя → Расширенные →
Режим разработчика). Это `ADMIN_ROLE_ID`. Пользователи с правами
администратора сервера всегда могут управлять опросами независимо от роли.

## 3. Локальный запуск / тест

```bash
cp .env.example .env
# впиши DISCORD_TOKEN и ADMIN_ROLE_ID в .env

pip install -r requirements.txt
python main.py
```

## 4. Как пользоваться

1. `/survey create name:minigame file:` — прикрепи `examples/minigame_feedback.json`
2. `/survey publish name:minigame` — в канале, где нужна кнопка
3. Участник нажимает "📋 Пройти опрос" → бот создаёт ему приватный канал
   и задаёт вопросы один за другим
4. `/survey results name:minigame` — получаешь CSV со всеми ответами

## 5. Формат JSON опроса

```json
{
  "title": "Название опроса",
  "intro": "Текст перед вопросами (описание в embed)",
  "outro": "Текст после последнего вопроса",
  "anonymous": true,
  "allow_multiple": false,
  "questions": [
    { "type": "scale", "text": "...", "min": 1, "max": 5,
      "min_label": "плохо", "max_label": "отлично" },
    { "type": "single", "text": "...", "options": ["A", "B", "C"] },
    { "type": "multi", "text": "...", "options": ["A", "B"], "other_option": true },
    { "type": "yes_no_detail", "text": "...", "yes_label": "Да (опишу)", "no_label": "Нет" },
    { "type": "text", "text": "Свободный ответ" }
  ]
}
```

Готовый пример под ваш опрос про мини-игру лежит в
`examples/minigame_feedback.json` — можно сразу загружать через `/survey create`.

## 6. Бесплатный хостинг 24/7

Подойдёт любой хост, поддерживающий Python-процесс с постоянным диском
(для файла `surveys.db`), например **Bot-Hosting.net** или **Wispbyte**.
Шаги одинаковые везде:

1. Залей все файлы проекта
2. Укажи команду запуска: `python main.py` (или `pip install -r requirements.txt && python main.py`)
3. Пропиши переменные окружения `DISCORD_TOKEN`, `ADMIN_ROLE_ID`, а также
   переменные веб-панели (см. раздел 7) в панели хостинга
4. Убедись, что диск/хранилище персистентно (не удаляется при рестарте) —
   иначе база `surveys.db` будет обнуляться

## 7. Веб-панель (создание опросов и отслеживание прохождений)

Бот теперь поднимает вместе с собой лёгкую веб-панель на aiohttp — **в том
же процессе и на том же порту**, что и сам бот. Это специально сделано так
для бесплатных хостингов (Wispbyte и подобные), где выделяется только
**один** внешний порт.

### Переменные окружения (`.env`)

```
WEB_ENABLED=1
WEB_HOST=0.0.0.0
WEB_PORT=14444           # ставь именно тот порт, который выдал хостинг
WEB_PASSWORD=длинный-случайный-пароль
```

Если `WEB_PASSWORD` не задан — панель не откроет доступ ни к чему (страница
покажет "панель отключена"). Это специально, чтобы никто не поднял пустую
админку по умолчанию.

### На Wispbyte / другом Pterodactyl-based бесплатном хостинге

- Проверь в панели хостинга (Network/Allocations), какой именно порт тебе
  выделен, и пропиши его в `WEB_PORT` — процесс должен слушать ровно тот
  порт, который проксирует хостинг наружу.
- `WEB_HOST` оставь `0.0.0.0` (не `127.0.0.1`), иначе снаружи контейнера
  панель будет недоступна.
- **На бесплатном тарифе обычно нет HTTPS** — панель будет открыта по
  простому `http://IP:PORT`. Логин и cookie сессии идут без шифрования.
  Это нормально для внутренней "для себя" админки, но: используй длинный
  случайный пароль, не переиспользуй его из других сервисов и не считай
  эту панель местом для по-настоящему секретных данных.
- Бесплатные ноды время от времени бывают нестабильны (даунтаймы), а
  аккаунт может потребовать периодического захода в панель хостинга,
  чтобы сервер не удалили за неактивность — учитывай это, если полагаешься
  на панель как на постоянный источник данных.

### Что умеет панель

- `/login` — вход по паролю (кука на 12 часов)
- `/surveys` — список всех опросов (с языком)
- `/surveys/new` — создание опроса через форму (без ручного JSON):
  заголовок, интро/аутро, язык, анонимность, повторное прохождение, конструктор
  вопросов (шкала/один вариант/несколько вариантов/да-нет/текст)
- `/surveys/<name>` — карточка опроса: сколько человек прошло, кто именно
  (или "Аноним #N", если опрос анонимный), дата прохождения, команда для
  приглашения людей на опрос (с кнопкой "Копировать")
- `/surveys/<name>/edit` — редактирование существующего опроса (включая
  смену языка — это и есть "миграция" опроса на другой язык)
- Клонирование опроса (кнопка "Клонировать" на карточке опроса) — создаёт
  копию под именем `<name>-copy` со всеми вопросами, дальше можно сразу
  отредактировать заголовок/язык/вопросы
- `/surveys/<name>/export.csv` — тот же CSV, что и `/survey results` в Discord
- Удаление опроса

### Язык опроса (ru / en)

При создании (и в любой момент — через редактирование) у опроса выбирается
язык: русский или английский. Он определяет все тексты, которые видит
**проходящий опрос** — кнопки "Готово"/"Done", "Другое"/"Other",
"Пройти опрос"/"Take survey", подписи по умолчанию для да/нет и т.д.
Ваши собственные тексты (заголовок, вступление/заключение, текст вопросов,
варианты ответов) вы всё равно пишете сами на любом языке — язык опроса
влияет только на служебные подписи бота.

Пример в JSON:
```json
{ "lang": "en", "title": "...", "questions": [...] }
```

### Своя подпись для варианта "Другое"

По умолчанию вариант "Другое" (или "Other" для английского языка) берётся
из языка опроса. Если нужно другое слово — например, "Свой вариант" —
можно задать `other_label` у конкретного вопроса (в форме — поле появляется
под чекбоксом "Добавить вариант «Другое»/«Other»"):

```json
{
  "type": "multi",
  "text": "Что понравилось?",
  "options": ["A", "B"],
  "other_option": true,
  "other_label": "Свой вариант"
}
```

Публикация кнопки опроса в конкретный Discord-канал по-прежнему делается
командой `/survey publish name:...` (она показана на странице опроса с
кнопкой "Копировать") — панели неоткуда знать, на каком сервере и в каком
канале её нужно опубликовать.

## Ограничения этой версии

- Нет графиков/дашборда — только таблица с датами и CSV-экспорт
- Веб-панель — однопользовательская (один общий пароль, без ролей)
- Приватные каналы (не Discord-нативные threads) создаются в отдельной
  категории — при очень большом количестве одновременных опросов сервер
  упрётся в лимит Discord на 500 каналов
